# Проверка нового процесса

Статус: передано владельцу. Агент проверил изменения чтением, команды ниже не выполнял. Эта проверка не запускает ВМ, продукт, deploy или тесты .NET.

Запускать из корня репозитория на хосте. Ниже Linux; на Windows использовать `python` вместо `python3` и путь exchange этой машины. Требуется Python 3.10 или новее. Секреты в команды не подставлять.

## Обёртка журналирования

Один короткий успешный запуск с этой инструкцией в качестве задания:

```bash
python3 lab/run-check.py --exchange "$HOME/Lab/exchange" --id workflow-ok-001 --request lab/check-workflow.md -- python3 -c "print('проверка обмена')"
```

Ожидается код 0, папка `checks/workflow-ok-001`, сохранённый вывод и итоговые метаданные. В `exit.txt` — 0. Повтор **той же команды с тем же id** должен отказать до запуска дочерней команды и сохранить первый результат.

Проверка ненулевого кода:

```bash
python3 lab/run-check.py --exchange "$HOME/Lab/exchange" --id workflow-fail-001 --request lab/check-workflow.md -- python3 -c "import sys; print('ожидаемый отказ'); sys.exit(7)"
```

Ожидается код 7 и тот же код в `exit.txt`, полный вывод в `output.log`. Это ожидаемый тестовый отказ, а не дефект обёртки.

Проверка отмены владельцем:

```bash
python3 lab/run-check.py --exchange "$HOME/Lab/exchange" --id workflow-stop-001 --request lab/check-workflow.md -- python3 -c "import time; print('можно нажать Ctrl+C', flush=True); time.sleep(60)"
```

Нажать Ctrl+C после сообщения. Ожидается завершение дочернего процесса и честный результат отмены; если завершение подтвердить не удалось, пакет не должен сообщать успешное окончание.

Для проверки привязки версии повторить успешный запуск с новым id после изменения отдельного неигнорируемого текстового файла. Отпечаток исходников должен измениться. Изменение только файлов в exchange не должно менять отпечаток, если exchange находится вне репозитория или исключён обёрткой из снимка.

## Перенос

Сначала прочитать [аудит](../docs/lab-transfer-audit.md) и заполнить локальный конфиг по [шаблону](transfer.example.json). Для первой проверки использовать временные каталоги и маленькие файлы. Не направлять непроверенный конфиг на существующий рабочий комплект.

Сценарии и команды проверки переноса перечислены в аудите. Проверка настоящей ВМ — отдельный запуск владельца после успешных проб на временном материале и полного выключения ВМ.

## Что вернуть

Сообщить пути к пакетам `workflow-*`, платформу и замечания по отмене. Для переноса — отчёт команды, путь к манифесту, проверяемый сценарий и код завершения. Ключи доступа не присылать. Агент анализирует результаты после сообщения владельца, без ожидания и опроса каталогов.
