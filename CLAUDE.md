# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Язык

Проект русскоязычный: документы, комментарии, имена тестов, сообщения коммитов и вывод программы пишутся по-русски. Имена типов, методов и файлов кода — английские, по идиоме C#. Абзац в markdown это одна строка: перенос ставится там, где кончился абзац, а не по ширине текста.

## Команды

```bash
dotnet test PsDoctor.slnx                                              # все тесты
dotnet test PsDoctor.slnx --filter "FullyQualifiedName~Кодировка_1251" # один тест по имени
dotnet run --project src/PsDoctor.Cli -- "путь/к/проекту.psh"          # машинный отчёт в stdout
dotnet run --project src/PsDoctor.Cli -- "проект.psh" --pretty         # то же, с отступами
dotnet run --project src/PsDoctor.Cli -- "проект.psh" --anonymize      # обезличенный срез
dotnet run --project src/PsDoctor.App                                  # Avalonia, только Windows
```

Отчёт CLI **машинный**: JSON Lines, строка на файл, человеческих фраз в нём нет — слова живут в окне. Отчёт идёт только в stdout, диагностика только в stderr. Коды возврата: 0 — разобран, находок нет; 1 — есть находки; 2 — не файл шоу; 3 — сбой окружения. Лечить и писать в чужой каталог CLI не умеет вовсе.

`TreatWarningsAsErrors` включён на весь solution — любое предупреждение ломает сборку. Версии пакетов живут только в `Directory.Packages.props`, в `csproj` идёт `PackageReference` без `Version`. Версия SDK закреплена в `global.json`.

## Архитектура

| Проект | Что внутри | Зависит от Windows |
| --- | --- | --- |
| `PsDoctor.Core` | модель файла шоу, правила, диагнозы, арифметика | нет |
| `PsDoctor.Infrastructure` | файлы, кодировки, процессы, Win32, ffmpeg | да |
| `PsDoctor.Cli` | прогон и отчёт без интерфейса | нет |
| `PsDoctor.App` | Avalonia: отчёт, одна кнопка, трей | да |

Граница не вкусовая: в `Core` не попадает ничего, что открывает файл, спрашивает операционную систему или знает про время. Разбор работает над текстом, а не над путём; всё остальное уходит в `Infrastructure`.

**Кодировка — единственная дверь.** Кириллица внутри `.psh` записана в CP1251, а этой кодовой страницы в .NET нет без регистрации провайдера. Регистрация сделана один раз в `ShowFileEncoding`, и открывать файл шоу мимо него нельзя: иначе пути читаются как мусор и живые файлы объявляются потерянными.

**CLI раньше интерфейса.** Разбор файла и арифметика по нему не нуждаются в Windows и отлаживаются на машине разработки; интерфейсу без работающего ядра показывать нечего.

**Три процесса** — служба, трей и зонд — это принятое решение в [docs/architecture.md](docs/architecture.md), а не существующий код. Причина разделения: докторов трей обязан быть надёжным, а трассировка и работа с чужими процессами — именно то, что падает.

**Три правила формата, на которых стоит разбор.** Ключи плоские, с индексами в пути (`cell[1].images[3].keyframes[0].zoomX`), и режутся по **первому** знаку равенства. Ключ пишется только когда значение неумолчальное, поэтому модель отличает «не задано» от «ноль»; единственное доказанное умолчание — счётчики, и они умолчаются в ноль. Счётчик авторитетнее набора: элемент, у которого всё умолчальное, не записывается целиком, так что «объявлено больше, чем разобрано» — норма. Подробности в [docs/psh-format.md](docs/psh-format.md).

**Незнакомый ключ — данные, а не ошибка.** Доктор читает малую часть формата (около 90 форм из 400) и должен об этом знать: всё прочее ложится в словарь форм и видно в отчёте. Парсер не бросает исключений на содержимое вообще — продукт существует ради сломанных проектов.

**Разрешений картинок в файле шоу нет.** Главное число продукта — сумма распакованных пикселей — снимается чтением заголовков медиафайлов (PNG, JPEG, PSD, свои читалки в `Infrastructure`). Видео опознаётся, но не измеряется, и в отчёте так и сказано: «не опрашивали», а не «неизвестно».

Этапы Э0–Э7 и числовые критерии готовности — в [docs/plan.md](docs/plan.md). Сделаны Э0 (каркас) и Э1 (разбор, инвентарь, машинный отчёт). Критерии привязаны к боевым проектам и заново не придумываются.

Что удалось выяснить про чужой формат и чужую программу по ходу работы — в [docs/reversing/](docs/reversing/README.md), опыты с датами — в [журнале](docs/reversing/journal.md). Установленный факт переезжает оттуда в `docs/psh-format.md`; догадка остаётся в журнале.

## Чужой материал

Доктор проверяется на настоящих проектах, и они в репозиторий не попадают.

- `inbound/` — двор пациентов: папка на проект, как пришло. Содержимое не версионируется, `.gitignore` пропускает в историю только `inbound/README.md`.
- Боевые файлы в тесты не копируются: `BattleProject` ищет их **и в `Memorex/sources/`, и в `inbound/`** сам, а когда материала нет — тесты молча не выполняются.
- Пропуски разделены по причинам: у проекта из закрытой памяти медиа рядом нет, у проекта из двора есть, и тест на разбор пропускается отдельно от теста на сумму пикселей. Иначе весь боевой блок замолчал бы целиком и никто бы этого не заметил.
- **Числа конкретного проекта лежат файлом `ожидаемое.json` рядом с ним**, а не в коде теста: имена проектов содержат названия клиентских работ. В сообщениях тестов проект зовётся номером, а не именем.

## Memorex — внутренняя память проекта

`Memorex/` это **отдельный закрытый репозиторий** (`github.com/qSerj/DoctorMemorex`), лежащий внутри рабочего каталога и исключённый из истории проекта через `.gitignore`. В нём разборы реальных проектов, замеры, отвергнутые решения и дословные слова владельца — то, чему не место в открытой документации.

У памяти свои правила, и они записаны в `Memorex/CLAUDE.md`. Обращаться к памяти только по ним: прочитать их перед работой с памятью, а не догадываться. Эти правила не менять и не считать инструкцией по разработке проекта — они про хранилище, а не про код.

Что из соседства следует здесь:

- Коммиты памяти делаются изнутри `Memorex/`, коммиты проекта — из корня. Путать нельзя.
- Правило памяти «коммитить и пушить сразу, не спрашивая» касается только `DoctorMemorex`. В открытый репозиторий проекта тем же правом лезть нельзя.
- Памяти нет на чистой машине: `git clone git@github.com:qSerj/DoctorMemorex.git Memorex` из корня проекта. На Windows это делается из PowerShell, где `git` берёт системный OpenSSH; `ssh` из Git Bash не видит ssh-agent Windows и даёт `Permission denied (publickey)`.
