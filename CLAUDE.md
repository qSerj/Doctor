# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

psdoctor — доктор проектов ProShow Producer: осматривает файл шоу `.psh` и окружение, говорит, что поедет, и чинит по кнопке. Второй продукт в том же решении — наблюдатель живой программы на стенде. Здесь только то, без чего агент ошибётся в любой задаче; остальное — по маршруту ниже. Что есть на этой машине — `CLAUDE.local.md`.

@CLAUDE.local.md

## Язык

Документы, комментарии, имена тестов, коммиты, вывод программы и ответы — по-русски. Имена типов, методов и файлов — английские, по идиоме C#. Абзац в markdown — одна строка.

## Агент пишет, владелец запускает

С 21.09.2026 агент проектирует, пишет код и тесты, ведёт документацию, делает ревью и разбирает готовые журналы. Владелец выполняет сборку, тесты, опыты, deploy, управляет ВМ и ProShow.

- **Можно:** читать и править файлы задачи, `git status/diff/log`, считать по уже готовому журналу.
- **Нельзя без прямого поручения конкретной операции:** build, tests, валидаторы, проверяемые скрипты, продукт, команды и опрос стенда, съёмка экрана. Доступ к Bash, SSH или MCP этого не меняет; «делай», «исправь», «продолжай» поручением не являются.
- **Цикл:** правка и ревью → задание проверки владельцу ([договор обмена](lab/README.md), команды — [docs/development.md](docs/development.md)) → ответ завершён → разбор принесённого результата. Файлы не ждать, повторов не запускать.
- **Статусы:** «реализовано», «передано на проверку», «проверено владельцем», «нужна правка». После проверки назвать версию и источник чисел; число, которого прогон не дал, не выдавать за факт.
- **Подагентов и фоновых задач не запускать**, если владелец прямо не попросил: при многоагентной работе токенов уходит больше, а пользы меньше.

## Git

- Fetch, pull и push открытого проекта делает владелец.
- Коммит — только по явной просьбе; переспрашивать не нужно. Сначала `git status` и `git diff`, потом добавить точные пути (без `git add -A`). Если в индексе чужие файлы — назвать их и остановиться. Без amend и без переписывания истории. Hook со сборкой или тестами не обходить: этот шаг передать владельцу.
- `Memorex/` — отдельный закрытый репозиторий внутри рабочего каталога. **Внутри него действуют только его правила из `Memorex/CLAUDE.md`**; их не менять. Коммиты памяти делаются изнутри `Memorex/`.

## Чужие данные и секреты

- Репозиторий открытый. Клиентские проекты (`inbound/`, `Memorex/sources/`) и их имена в историю не попадают; в тестах проект зовётся номером.
- **Хранилище проектов владельца — только чтение.** Туда не пишется ничего, включая временные файлы и результаты.
- Ключи и секреты в репозиторий, журналы и аргументы команд не попадают.

## Что читать под задачу

Читать только то, что относится к задаче; остальное не загружать.

- **Код компонента** — его `README.md`, дальше только названный там профильный документ. Разбор `.psh` — [docs/psh-format.md](docs/psh-format.md), правила приёмки — [docs/diagnostics.md](docs/diagnostics.md), слои и наблюдатель — [docs/architecture.md](docs/architecture.md).
- **Стенд, ВМ, SSH, MCP, доставка, `lab/`** — [lab/CLAUDE.md](lab/CLAUDE.md), при необходимости [docs/lab.md](docs/lab.md).
- **Этап плана** — его раздел в [docs/plan.md](docs/plan.md); правила раздела записаны там же. Для инфраструктурных, эксплуатационных и мелких задач план не нужен; мелочи ведутся в [docs/chores.md](docs/chores.md).
- **Новое исследование поведения ProShow, формата или правила диагностики** — сначала проверить, что уже известно по этой теме: [docs/reversing/](docs/reversing/README.md), затем нужные записи в `Memorex/`. Первой строкой сказать, что нашлось. Для обычной разработки, инфраструктуры и документации журнал реверсинга и `Memorex/` не читать.
- **Боевые проекты в тестах** — [inbound/README.md](inbound/README.md).
- **Задача требует другой машины** — не имитировать, назвать, чего не хватает: [docs/environments.md](docs/environments.md).
- **Документация** — карта, статусы и раунды `design/` описаны в [docs/README.md](docs/README.md). Предложение не становится требованием без решения владельца.
