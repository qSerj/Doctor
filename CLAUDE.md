# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

psdoctor — доктор проектов ProShow Producer: осматривает файл шоу и окружение, говорит, что поедет, и чинит по кнопке; второй продукт в том же решении — наблюдатель живой программы на стенде. Здесь — как работать с проектом на любой машине. Что доступно на этой машине — `CLAUDE.local.md` (ниже). Как устроены подсистемы — `docs/` и README рядом с кодом. Что происходило раньше — `Memorex/` и `docs/reversing/journal.md`.

@CLAUDE.local.md

## Язык

Документы, комментарии, имена тестов, сообщения коммитов, вывод программы и ответы владельцу — по-русски. Имена типов, методов и файлов кода — английские, по идиоме C#. Абзац в markdown — одна строка: перенос там, где кончился абзац, а не по ширине текста.

## Роли: агент пишет, владелец запускает

С 21.09.2026 агент — архитектор и разработчик: проектирует, пишет код и тесты, ведёт документацию, делает ревью, разбирает готовые журналы. Владелец — исполнитель прогонов: сборка, тесты, опыты, deploy, ВМ, ProShow, кнопки и снимки экрана.

- **Самому можно:** читать и править файлы задачи, `git status/diff/log`, локальный подсчёт по уже готовому журналу.
- **Самому нельзя:** build, tests, валидаторы, проверяемые скрипты, продукт, команды и опрос стенда, съёмка экрана. Наличие Bash, SSH или MCP к стенду не меняет этого. Исключение — прямое поручение конкретной операции; «делай», «исправь», «продолжай» его не дают.
- **Цикл:** правка и ревью → задание проверки владельцу → ответ завершён → владелец приносит результат → разбор и следующая правка. Файлы не ждать, стенд не опрашивать, повторов не запускать. Договор обмена (`<exchange>/checks/<id>/`, `run-check.py`, чтение `request.md` → `run.json` → `exit.txt` → нужные куски `output.log`) — в [lab/README.md](lab/README.md). Нет `exit.txt` — прогон не завершён, а не «успешен».
- **Статусы:** «реализовано», «передано на проверку», «проверено владельцем», «нужна правка». Реализация без результатов — не проверка. После проверки назвать версию и источник чисел.
- **Подагентов и фоновых задач не запускать**, если владелец прямо не попросил: опыт многоагентной работы — токенов уходит больше, пользы меньше.

## Git

- Fetch/pull/push открытого проекта делает владелец.
- Коммит — только по явной просьбе («комить» и т. п.); повторно не переспрашивать. Перед этим прочитать `git status` и `git diff`, добавить **точные пути** задачи (без `git add -A` и масок). Если в индексе уже лежит чужое — назвать файлы и остановиться. Не смешивать чужие изменения, не делать amend и не переписывать историю. Hook, запускающий сборку или тесты, не обходить и не отключать — этот шаг передать владельцу. В ответе — hash, тема и что осталось вне коммита.
- `Memorex/` — отдельный закрытый репозиторий (`github.com/qSerj/DoctorMemorex`) внутри рабочего каталога, исключён через `.gitignore`. **Внутри него действуют только его собственные правила из `Memorex/CLAUDE.md`**, включая порядок pull и push; прочитать их перед работой с памятью и не править. Коммиты памяти — изнутри `Memorex/`, проекта — из корня. На чистой машине владелец клонирует: `git clone git@github.com:qSerj/DoctorMemorex.git Memorex`.

## Команды для владельца

Агент их не выполняет, а называет в задании проверки.

```bash
dotnet test PsDoctor.slnx                                              # все тесты
dotnet test PsDoctor.slnx --filter "FullyQualifiedName~Кодировка_1251" # один тест по имени
dotnet run --project src/PsDoctor.Cli -- "путь/к/проекту.psh"          # машинный отчёт в stdout
dotnet run --project src/PsDoctor.Cli -- "проект.psh" --pretty         # то же, с отступами
dotnet run --project src/PsDoctor.Cli -- "проект.psh" --anonymize      # обезличенный срез
dotnet run --project src/PsDoctor.App                                  # Avalonia, только Windows
dotnet run --project src/PsDoctor.Workbench                            # пульт наблюдателя, где угодно
lab/observer.sh                                                        # собрать наблюдатель, доставить на стенд, прогнать тесты
dotnet run --project src/PsDoctor.Cli -- observe health                # версия и коммит наблюдателя на стенде
dotnet run --project src/PsDoctor.Cli -- observe run сценарий.txt --follow  # прогон сценария, факты в stdout
```

- **Коды возврата CLI:** 0 — разобран, находок нет; 1 — есть находки; 2 — не файл шоу; 3 — сбой окружения. У `observe` своя таблица: 0 — выполнено, 1 — сценарий не выполнен, 2 — отказ наблюдателя, 3 — сбой окружения. `observe` берёт адрес и ключ из `PSDOCTOR_OBSERVER_URL` и `PSDOCTOR_OBSERVER_KEY_FILE` или из `--url` и `--key-file`.
- **Отчёт CLI машинный:** JSON Lines, строка на файл, без человеческих фраз, потому что слова живут в окне. Отчёт — только stdout, диагностика — только stderr. Лечить и писать в чужой каталог CLI не умеет вовсе.
- **Сборка:** `TreatWarningsAsErrors` на весь solution, любое предупреждение ломает сборку. Версии пакетов — только в `Directory.Packages.props`, в `csproj` пишется `PackageReference` без `Version`. `global.json` закрепляет **линейку** SDK (`10.0.100`, `rollForward: latestFeature`); точную версию не ставить — на разных машинах разные SDK.
- Корень репозитория — текущий checkout (`git rev-parse --show-toplevel`); абсолютные пути в скрипты и правила не зашиваются.

## Архитектура

| Проект | Что внутри | Windows |
| --- | --- | --- |
| `PsDoctor.Core` | модель файла шоу, правила, диагнозы, арифметика; факты, журнал сеанса, контракт API, разбор сценариев | нет |
| `PsDoctor.Infrastructure` | файлы, кодировки, процессы, Win32, ffmpeg, читалки заголовков медиа; запуск программы под заданием, окна, действия сценария | да |
| `PsDoctor.Cli` | прогон и отчёт без интерфейса; подкоманда `observe` | нет |
| `PsDoctor.Observer` | наблюдатель: Kestrel, маршруты, сеанс наблюдения | да |
| `PsDoctor.Observer.Client` | типизированный клиент API наблюдателя | нет |
| `PsDoctor.Workbench` | Avalonia: пульт владельца — сценарии, лента фактов, диалоги стенда | нет |
| `PsDoctor.App` | Avalonia: отчёт, одна кнопка, трей — пока каркас | да |

Тесты — пять проектов xUnit в `tests/`.

- **Граница `Core`:** в него не попадает ничего, что открывает файл, спрашивает ОС или знает про время. Разбор работает над текстом, а не над путём; остальное уходит в `Infrastructure`. Поэтому разбор и правила отлаживаются под Linux, а интерфейсу без работающего ядра показывать нечего.
- **Кодировка — единственная дверь.** Кириллица в `.psh` записана в CP1251, а её в .NET нет без регистрации провайдера. Регистрация сделана один раз в `ShowFileEncoding`; открывать файл шоу мимо него нельзя, иначе пути читаются как мусор, а живые файлы объявляются потерянными.
- **Формат `.psh`:** ключи плоские, с индексами в пути (`cell[1].images[3].keyframes[0].zoomX`), и режутся по **первому** `=`. Ключ пишется только при неумолчальном значении, поэтому модель отличает «не задано» от «ноль»; доказанное умолчание одно — счётчики умолчаются в ноль. Счётчик авторитетнее набора: «объявлено больше, чем разобрано» — норма. Подробно — [docs/psh-format.md](docs/psh-format.md).
- **Парсер не бросает исключений на содержимое вообще:** продукт существует ради сломанных проектов. Незнакомый ключ — данные: доктор читает малую часть формата, остальное ложится в словарь форм и видно в отчёте.
- **Разрешений картинок в файле шоу нет.** Главное число — сумма распакованных пикселей — снимается из заголовков медиа (PNG, JPEG, PSD; свои читалки в `Infrastructure`). Видео опознаётся, но не измеряется, и в отчёте так и сказано: «не опрашивали», а не «неизвестно».
- **Правила приёмки — данные:** класс с устойчивым идентификатором, уровнем исполнения и уверенностью из карточки [docs/diagnostics.md](docs/diagnostics.md). Находка — правило плюс конкретный объект с адресом, переживающим правку проекта, и числа срабатывания; фраз в ней нет.
- **Порогов нет ни у одного правила, и это не недоделка.** Код 1 дают только находки выше порога, поэтому пока исход всегда 0. Числа для порогов набираются работой; не придумывать их.
- **Наблюдатель** — долгоживущий процесс в сеансе пользователя на стенде: запускает ProShow под заданием Windows, видит куст процессов и окна, выполняет короткие сценарии (`launch`, `press`, `render`, `close`, ожидания) и отдаёт поток фактов по HTTP с ключом Bearer. Вердиктов не выносит: факт — номер, время, вид и числа. Окна читаются только из сеанса пользователя, не из службы и не из нулевого сеанса SSH. Устройство — [docs/architecture.md](docs/architecture.md); «три процесса» (служба, трей, зонд) там — предложение, а не код.
- **README рядом с кодом:** у каждого проекта свой — назначение, граница, с чего читать, чего в нём нет. Код он не пересказывает (маршруты, виды фактов и команды находятся `grep`). Правится тем же коммитом, который двигает границу проекта; отдельного прохода «актуализировать документацию» нет.

## Оснастка `lab/`

Всё в `lab/` — обвязка стенда; в поставку не едет ни строки, и как архитектуру её не читать. Первая строка каждого скрипта называет вид: `Оснастка стенда` (постоянная), `Цикл опыта` (живёт, пока живёт пункт критерия), `Зонд опыта` (одноразовый; ответ уезжает в журнал реверсинга, сам скрипт удаляется). Зонд не чинят и не развивают. Подробно — [lab/README.md](lab/README.md), стенд — [docs/lab.md](docs/lab.md), перенос между машинами — [docs/lab-transfer-audit.md](docs/lab-transfer-audit.md) (выполняет владелец скриптом `lab/transfer.py`, без ИИ).

## Чужой материал

Доктор проверяется на настоящих клиентских проектах, и в открытый репозиторий они не попадают.

- `inbound/` — двор пациентов: папка на проект, как пришло. В историю идёт только `inbound/README.md`.
- Боевые файлы в тесты не копируются: `BattleProject` сам ищет их в `Memorex/sources/` и `inbound/`, а без материала тесты молча не выполняются. Пропуски разделены по причинам (у проекта из памяти медиа рядом нет, у проекта из двора есть), иначе боевой блок замолчал бы целиком незаметно.
- Числа проекта лежат в `ожидаемое.json` рядом с ним, а не в коде теста; там же раздел находок. В сообщениях тестов проект зовётся номером, а не именем: имена содержат названия клиентских работ.
- Метка `inbound/.calibrated` (свойство машины, не версионируется): где она есть, пропажа ожидаемых чисел — поломка; где нет — такие тесты не выполняются.
- **Хранилище владельца** — большая выборка вне репозитория, путь в `CLAUDE.local.md`. **Только чтение: не писать туда ничего**, включая временные файлы и результаты. Материал не проверен и нормы не доказывает — условия в [Э2.1](docs/plan.md).
- Профиль по одному проекту — наблюдение, а не закон; пачка его регулярно опровергает.

## Как вести работу

- **Сначала накопанное.** Прежде чем предлагать опыт, поиск или инструмент, поискать в `Memorex/memory/`, `docs/reversing/journal.md` и `Memorex/actions/open.md` и первой строкой сказать, что там уже есть.
- **Числа — из прогона, а не из рассуждения.** Число, которого прогон не дал, в критерий не ставится; ставится способ его получить.
- **Задача, требующая другой машины**, не имитируется: назвать, чего не хватает, и отложить. Что где возможно — [docs/environments.md](docs/environments.md).
- **Раздел этапа в [docs/plan.md](docs/plan.md) — единственный вход в работу**, без памяти о прежних обсуждениях. Он годен, когда в нём есть состав, граница с причиной, критерий, проверяемый числом или командой, и ссылки на решения. Критерий, требующий того, чего на этапе нет, — не критерий. Исполнитель этапа дописывает в план только свой раздел: пометку «сделано» и таблицу чисел; мелкие доработки идут в [docs/chores.md](docs/chores.md). Текущее состояние этапов — в плане, не здесь.
- **Реверсинг:** что выяснено про чужой формат и программу — [docs/reversing/](docs/reversing/README.md); догадка живёт в журнале, установленный факт переезжает в `docs/psh-format.md`.
