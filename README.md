# psdoctor

Доктор проектов для ProShow Producer. Не заменяет мёртвую программу, а обслуживает её снаружи: осматривает проект и окружение, смотрит за живой программой и человеческим языком говорит, что мешает работать и что с этим сделать.

Photodex закрылись около 2020 года. ProShow остался 32-битным и без сопровождения: его проекты грузятся десятки минут, он виснет на рендере и не объясняет, что не так. Между «программа мертва» и «программа работает нормально» лежит не переписывание, а обслуживание.

## Два продукта

**App** — Doctor монтажёра. Самостоятельное приложение в трее для человека без технической подготовки; удобство и понятность важнее всего. Он **применяет готовые рецепты**: осматривает проект, узнаёт известную проблему и даёт совет с понятным действием. Если не узнал — молчит.

**Workbench** — лаборатория инженера. Здесь опытами на стенде и на машине монтажёра находят паттерны сбоев, из которых вместе с агентом получаются рецепты для App.

Под обоими — **наблюдатель**: процесс на машине с ProShow, который запускает программу или подключается к ней, пишет факты о процессах, окнах и файловой активности (ETW) и отдаёт их по одному API. App говорит с ним локально, Workbench — локально или по сети.

## Почему программа глючит — предмет исследования

Причина не одна. Программа виснет и падает от сочетания условий: состояние её кэшей, служебные файлы рядом с проектом, запускаемые ею рабочие процессы, кодеки в системе, размер и формат исходников. Что из этого и в каком сочетании действительно роняет её — выясняется наблюдением, а не выводится заранее.

Одно из подозрений измерено: программа 32-битная, с флагом больших адресов, и на 64-битной Windows может занять до 4 ГБ. На рендере небольшого проекта с 4K-видео её память скачком доходила до 2.8 ГБ. Это довод, но не объяснение всех сбоев сразу.

Автоматически с проектом и материалом доктор ничего не делает: о неоптимальном материале он сообщает, а менять его — решение человека.

## Что работает сейчас

- Разбор `.psh`, инвентарь материала и шесть правил приёмки; машинный отчёт CLI, прогон по хранилищу проектов.
- App: трей, проверка проекта с рекомендациями, мастер «Решить проблему» с безопасным восстановлением служебных файлов ProShow, запуск и подключение наблюдения.
- Наблюдатель: запуск ProShow под заданием Windows, окна и диалоги, короткие сценарии вплоть до рендера без человека, поток фактов с переподключением; ETW и пассивное подключение реализованы и ждут проверки.
- Workbench: сценарии, лента фактов, кнопки диалогов, пакеты опытов для разбора.

Дальше по [плану](docs/plan.md): установщик со сторожем, первый рецепт от паттерна до совета в App, измерение видео, откат к резервным срезам проекта. Подробный снимок — [как есть на 23.09.2026](design/tier2/baseline.md).

## Состав

```text
src/PsDoctor.Core             модель .psh, правила, арифметика, факты, сценарии. Без I/O и без Windows
src/PsDoctor.Infrastructure   файлы, кодировки, медиа, процессы, Win32, ffmpeg
src/PsDoctor.Cli              машинный отчёт и подкоманда observe
src/PsDoctor.Observer         наблюдатель живой программы и ETW-помощник
src/PsDoctor.Observer.Client  типизированный клиент API наблюдателя
src/PsDoctor.Workbench        Avalonia: лаборатория инженера
src/PsDoctor.App              Avalonia: Doctor монтажёра — окно, трей, мастер
tests/                        пять проектов xUnit
lab/                          оснастка стенда, в поставку не входит
inbound/                      двор для пациентов, в историю не попадает
```

У каждого проекта рядом с кодом свой `README.md`: граница, с чего читать, чего в нём нет.

## Сборка

```bash
dotnet test PsDoctor.slnx
```

Ядро, CLI и Workbench собираются и проверяются где угодно. App и наблюдатель — только Windows, и это решение, а не следствие: пациент живёт там.
