# psdoctor

Доктор проектов для ProShow Producer. Не заменяет мёртвую программу, а обслуживает её снаружи: осматривает проект и окружение, человеческим языком говорит, что именно поедет, и чинит по кнопке.

Photodex закрылись около 2020 года. ProShow остался 32-битным и без сопровождения: его проекты грузятся десятки минут, он виснет на рендере и не объясняет, что не так. Между «программа мертва» и «программа работает нормально» лежит не переписывание, а обслуживание.

## Почему программа глючит — предмет исследования

Причина не одна. Программа виснет и падает от сочетания условий: состояние её кэшей, служебные файлы рядом с проектом, запускает ли она рабочие процессы (а запускает не всегда — то ли по своим настройкам, то ли от состава проекта, например от видео среди исходников), кодеки в системе, размер исходников. Что из этого и в каком сочетании действительно роняет её — выясняется наблюдением, а не выводится заранее.

Одно из подозрений измерено: программа 32-битная, с флагом больших адресов, и на 64-битной Windows может занять до 4 ГБ. На рендере небольшого проекта с 4K-видео её память скачком доходила до 2.8 ГБ. Картинки одного боевого проекта занимают 1.74 ГБ распакованными. Это сильный довод уменьшать исходники, но не объяснение всех глюков сразу.

Отсюда устройство доктора: он не только считает по файлу проекта, но и смотрит за живой программой — что она читает, какие процессы запускает, где встала. Особенно при рендере: там программа не сообщает ничего.

## Состав

```text
src/PsDoctor.Core             модель .psh, правила, диагнозы, арифметика. Без I/O и без Windows
src/PsDoctor.Infrastructure   файлы, кодировки, процессы, Win32, ffmpeg
src/PsDoctor.Cli              прогон и отчёт без интерфейса
src/PsDoctor.App              Avalonia: отчёт, одна кнопка, трей
tests/PsDoctor.Core.Tests     xunit
inbound/                      двор для пациентов, в историю не попадает
```

## Сборка

```bash
dotnet test PsDoctor.slnx
```

Ядро и CLI собираются и проверяются где угодно. Целевая платформа продукта — только Windows, и это решение, а не следствие: пациент живёт там.
