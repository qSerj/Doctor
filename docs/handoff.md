# Перенос работы между машинами

Статус: **реализовано 24.09.2026**, приёмы 26–29.09.2026 прошли без препятствий; **выжимки чатов (формат 3) — реализовано 29.09.2026, передано на проверку**. Прежний hand-off (bundle, dirty patch, `inspect`) снят: он сливал два живых состояния, а чаты и опыты не переносил ([открытые вопросы](open-questions.md#переход-между-машинами)).

Принцип: в момент перехода у работы **одна машина-источник**. Принимающая машина её состояние не сливает со своим, а перематывается к нему; любое расхождение — остановка с объяснением. Скрипт `scripts/handoff.py` работает без ИИ; когда ИИ доступен, тот же скрипт запускает skill `handoff` и добавляет то, чего скрипт не умеет: запись «где остановились» и разбор отказов.

## Настройка машины

Один раз скопировать `handoff.local.example.json` в `handoff.local.json` (в Git не попадает) и указать:

| Поле | Что это |
| --- | --- |
| `machine` | имя машины латиницей: `WORK`, `HOME` |
| `transit_root` | каталог на переносном накопителе |
| `exchange_checks` | `<exchange>/checks` этой машины — пакеты проверок |
| `chats_readonly` | куда класть принятые выжимки и копии сессий; по умолчанию `~/Lab/chats` |
| `digests` | куда `digest` пишет выжимку перед уходом; по умолчанию `~/Lab/digests` |

## Уходя с машины

1. `python3 scripts/handoff.py digest` (на Windows — `python`) — выжимка чатов, её сверка с Git и Memorex (skill `handoff`, шаг 2).
2. Дописать раздел в конец `Memorex/memory/Ход работы.md`: где остановились, что дальше, что открыто, сверена ли выжимка. Закоммитить и отправить Memorex.
3. `python3 scripts/handoff.py export`. С `--push` скрипт сам отправит неотправленные коммиты.

`export` останавливается, если в Doctor или Memorex есть незакоммиченное, неотправленное (без `--push`) или если origin впереди — тогда источник устарел. Сам скрипт не коммитит никогда. Пакет собирается в `.building-*` и получает имя `<дата>-<машина>` только целиком; прежние пакеты не трогаются.

Состав пакета:

- `git/doctor.bundle`, `git/memorex.bundle` — ветки и теги, если на приёме нет сети;
- `chats/digest.md` — выжимка сессий, изменённых после прошлого пакета этой машины;
- `chats/sessions/*.jsonl` — копии тех же сессий: запас на случай, когда выжимку не успели сверить на источнике;
- `chats/memory/` — память агента;
- `experiments/lab-exchange-checks/` — пакеты проверок;
- `experiments/repo-artifacts/` — игнорируемый `artifacts/` без `.handoff-backup`;
- `context/CLAUDE.local.md` — профиль источника, только для справки;
- `README.md` — «где остановились» (последний раздел страницы `Ход работы`), состав, команды приёма;
- `manifest.json` — HEAD репозиториев и SHA-256 каждого файла.

Не входят: ВМ (перенос ВМ — аварийный `lab/transfer.py`, [аудит](lab-transfer-audit.md)), `inbound/`, хранилище проектов, ключи, `handoff.local.json`, `bin/obj`.

## Придя на машину

```text
python3 scripts/handoff.py receive <пакет>
python3 scripts/handoff.py receive <пакет> --apply
```

`<пакет>` — имя в `transit_root` или путь. Без `--apply` рабочее дерево и ветки не меняются; сверка может сделать `git fetch` и положить ветки из bundle в `refs/handoff/*`. Первая команда проверяет контрольные суммы, печатает план (`=` совпадает, `+` будет сделано, `!` препятствие) и «где остановились». Вторая выполняет план, только если препятствий нет.

| Что | Как принимается | Препятствие |
| --- | --- | --- |
| Doctor, Memorex | `merge --ff-only` до HEAD из пакета; объекты из origin, без сети — из bundle | незакоммиченное здесь; другая ветка; здесь коммиты, которых нет в пакете; истории разошлись |
| Пакеты проверок | недостающие копируются | одноимённый пакет с другим содержимым |
| `artifacts/` | берётся версия пакета, здешние лишние файлы остаются; каждый заменяемый сначала кладётся в `artifacts/.handoff-backup/<пакет>/` | — |
| Выжимка и копии сессий | в `chats_readonly/<пакет>/`, только для чтения; в `~/.claude/projects/` не попадают: продолжать чужую сессию нельзя. Пакет формата 2 принимается по-старому | — |
| `memory/` агента | недостающие файлы добавляются; различающиеся перечисляются и остаются здешними | — |
| `CLAUDE.local.md` | не трогается | — |

Коды выхода: 0 — принято или препятствий нет; 1 — есть препятствия, ничего не изменено; 2 — ошибка (конфиг, повреждённый пакет, незакоммиченное при export).

## Чего скрипт не делает

Не сливает, не коммитит, не удаляет, не собирает и не трогает ВМ. Различающуюся `memory/` агента и различающийся `MEMORY.md` сводит человек или skill. Если лимиты кончились и раздел «Ход работы» не дописан, README покажет последний имеющийся — это видно по дате в заголовке раздела.

## Выжимки чатов

`digest` и `export` берут сессии, изменённые после прошлого пакета этой машины (время — из `manifest.json` её последнего пакета в `transit_root`; пакета нет — с начала дня), и вынимают из них реплики владельца и агента после этого времени: без вывода инструментов, размышлений, служебных вставок и подагентов. Сессия с вызовом skill `handoff` помечается «чат переноса», но не выбрасывается: в ней бывает и рабочий разговор после приёма. `digest --from <каталог> [--since <время>]` делает выжимку из любого каталога `.jsonl` — например, из принятых раньше полных копий.

Копии `.jsonl` едут в пакете не «на всякий случай», а как запас для сверки: если на источнике кончился лимит и выжимку не сверили, это делает рабочий чат на приёме — по `digest.md`, а при сомнении по копиям. Сверена ли выжимка, видно по последней строке раздела «Ход работы»; раздел старше пакета — значит, не сверена.

## Предложение: выжимки чатов вместо копий

Статус: **реализовано 29.09.2026** (раздел выше) с двумя отличиями по решению владельца: выжимка и копии свежих сессий едут в пакете, чтобы сверку можно было сделать на приёме; чат переноса помечается, а не пропускается. Ниже — исходное предложение.

**Почему.** Копии `.jsonl` на машине с другим путём проекта ложатся в `chats_readonly` и там не читаются: `--resume` их не находит, а продолжать сессию с чужой машины вредно — её контекст состоит из чужих путей, команд и состояния файлов. Из чата на другой машине нужен не разговор, а то, что не попало в Git и Memorex: решения и оговорки владельца, сказанные словами, найденные расхождения, выясненное агентом и не записанное. Пример — приём 23.09.2026: из шести сессий почти всё уже было в Git, но одна находка (паттерн Э4.4 записан фактом, а он гипотеза) жила только в чате и была перенесена в план коммитом `2ad9f36`.

**Как.** Контекст едет через Git — документы, Memorex, «Ход работы», — а не через пакет.

1. **Скрипт.** `export` вынимает из сессий, изменённых после прошлого экспорта с этой машины (время — из `manifest.json` последнего её пакета в `transit_root`; пакета нет — за сегодня), только реплики владельца и агента, без вывода инструментов и служебных вставок, в текст вне репозитория и вне пакета. Мегабайты `.jsonl` становятся десятками килобайт. Механика, ИИ не нужен.
2. **Skill, шаг «Уходя».** Агент читает этот текст и сверяет с коммитами за тот же срок и с Memorex. Не записанное нигде показывает владельцу списком; принятое — в Memorex по его правилам и в раздел «Ход работы». Чаты переноса пропускаются: в них нет рабочего содержания.
3. **Пакет.** `chats/` из состава убирается; `memory/` агента остаётся. Копии `.jsonl` — только по флагу, для разбора.
4. **Приём.** `receive` чатов не копирует: выжимка уже в Memorex и приходит с перемоткой.

**Цена.** Чтение нескольких десятков тысяч токенов текста за рабочий день и ответы владельца по списку. Дешевле, если каждый рабочий чат сам пишет выжимку в конце, но это держится на дисциплине и пропадает, когда кончился лимит.

**Открыто.** Закрыто реализацией: чат переноса узнаётся по вызову skill `handoff`; отдельного флага и срока хранения копий нет — копии свежих сессий едут в каждом пакете, а пакеты на накопителе не удаляются.
