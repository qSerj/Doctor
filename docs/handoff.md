# Перенос работы между машинами

Статус: **реализовано 24.09.2026, передано на проверку**. Прежний hand-off (bundle, dirty patch, `inspect`) снят: он сливал два живых состояния, а чаты и опыты не переносил ([открытые вопросы](open-questions.md#переход-между-машинами)).

Принцип: в момент перехода у работы **одна машина-источник**. Принимающая машина её состояние не сливает со своим, а перематывается к нему; любое расхождение — остановка с объяснением. Скрипт `scripts/handoff.py` работает без ИИ; когда ИИ доступен, тот же скрипт запускает skill `handoff` и добавляет то, чего скрипт не умеет: запись «где остановились» и разбор отказов.

## Настройка машины

Один раз скопировать `handoff.local.example.json` в `handoff.local.json` (в Git не попадает) и указать:

| Поле | Что это |
| --- | --- |
| `machine` | имя машины латиницей: `WORK`, `HOME` |
| `transit_root` | каталог на переносном накопителе |
| `exchange_checks` | `<exchange>/checks` этой машины — пакеты проверок |
| `chats_readonly` | куда класть чаты с машины, где путь проекта другой; по умолчанию `~/Lab/chats` |

## Уходя с машины

1. Дописать раздел в конец `Memorex/memory/Ход работы.md`: где остановились, что дальше, что открыто. Закоммитить и отправить Memorex.
2. `python3 scripts/handoff.py export` (на Windows — `python`). С `--push` скрипт сам отправит неотправленные коммиты.

`export` останавливается, если в Doctor или Memorex есть незакоммиченное, неотправленное (без `--push`) или если origin впереди — тогда источник устарел. Сам скрипт не коммитит никогда. Пакет собирается в `.building-*` и получает имя `<дата>-<машина>` только целиком; прежние пакеты не трогаются.

Состав пакета:

- `git/doctor.bundle`, `git/memorex.bundle` — ветки и теги, если на приёме нет сети;
- `chats/<имя каталога проекта>/` — сессии Claude Code и `memory/` агента;
- `experiments/lab-exchange-checks/` — пакеты проверок;
- `experiments/repo-artifacts/` — игнорируемый `artifacts/` без `.handoff-backup`;
- `context/CLAUDE.local.md` — профиль источника, только для справки;
- `README.md` — «где остановились» (последний раздел страницы `Ход работы`), состав, команды приёма;
- `manifest.json` — HEAD репозиториев и SHA-256 каждого файла.

Не входят: ВМ (перенос ВМ — аварийный `lab/transfer.py`, [аудит](lab-transfer-audit.md)), `inbound/`, хранилище проектов, ключи, `handoff.local.json`, `bin/obj`.

## Придя на машину

```text
python3 scripts/handoff.py receive <пакет>
python3 scripts/handoff.py receive <пакет> --apply
```

`<пакет>` — имя в `transit_root` или путь. Без `--apply` рабочее дерево и ветки не меняются; сверка может сделать `git fetch` и положить ветки из bundle в `refs/handoff/*`. Первая команда проверяет контрольные суммы, печатает план (`=` совпадает, `+` будет сделано, `!` препятствие) и «где остановились». Вторая выполняет план, только если препятствий нет.

| Что | Как принимается | Препятствие |
| --- | --- | --- |
| Doctor, Memorex | `merge --ff-only` до HEAD из пакета; объекты из origin, без сети — из bundle | незакоммиченное здесь; другая ветка; здесь коммиты, которых нет в пакете; истории разошлись |
| Пакеты проверок | недостающие копируются | одноимённый пакет с другим содержимым |
| `artifacts/` | берётся версия пакета, здешние лишние файлы остаются; каждый заменяемый сначала кладётся в `artifacts/.handoff-backup/<пакет>/` | — |
| Чаты | путь проекта совпадает — в `~/.claude/projects/…`, `--resume` работает; сессия заменяется только более длинной; путь другой — в `chats_readonly/<пакет>/` для чтения | — |
| `memory/` агента | недостающие файлы добавляются; различающиеся перечисляются и остаются здешними | — |
| `CLAUDE.local.md` | не трогается | — |

Коды выхода: 0 — принято или препятствий нет; 1 — есть препятствия, ничего не изменено; 2 — ошибка (конфиг, повреждённый пакет, незакоммиченное при export).

## Чего скрипт не делает

Не сливает, не коммитит, не удаляет, не собирает и не трогает ВМ. Различающуюся `memory/` агента и различающийся `MEMORY.md` сводит человек или skill. Если лимиты кончились и раздел «Ход работы» не дописан, README покажет последний имеющийся — это видно по дате в заголовке раздела.
