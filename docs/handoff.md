# Офлайн hand-off

Статус: **Требует проверки. Не использовать до пересмотра подхода** (решение владельца 23.09.2026: подход сбоит целиком, см. [открытые вопросы](open-questions.md#переход-между-машинами)). Ниже — описание замысла, а не рабочая инструкция.

Hand-off — лёгкий автономный пакет рабочего состояния Doctor. GitHub остаётся обычным каналом синхронизации, а hand-off — гарантированной офлайн-передачей между машинами; интернет, GitHub и ИИ ему не нужны.

## Закончил работу на машине

1. Скопировать `handoff.local.example.json` в `handoff.local.json` и один раз указать `machine`, корень переносного накопителя и явно разрешённые дополнительные материалы. Секреты и ключи не включаются.
2. Выполнить `python3 scripts/handoff.py export` из любого места внутри репозитория.
3. Передать владельцу каталог, названный в выводе `OK`. Папка `.building-*` означает оборванный экспорт и не является пакетом.

Экспорт сохраняет репозитории Doctor и, если он есть, Memorex: branch, HEAD, локальные Git-коммиты в bundle, status/log/remotes, dirty patch и untracked-файлы. `latest.txt` меняется только после проверки bundle, архивов и SHA-256.

## Пришёл на другую машину

Создать локальный `handoff.local.json`, указать её transit и выполнить:

```text
python3 scripts/handoff.py inspect
```

Можно передать имя или путь конкретного пакета. Команда ничего не меняет в рабочем дереве: показывает HEAD, branch, clean/dirty, modified/untracked и отношение историй (`handoff ahead`, `local ahead` или `histories diverged`). Восстановление выполняется вручную после проверки и не затирает локальные изменения.

## Если нет интернета

Ничего особенного: `export` и `inspect` работают локально и не выполняют fetch, pull, push или обращения к GitHub. Пакет переносится обычным копированием каталога на накопитель.

Полный архив Doctor и перенос ВМ остаются отдельным аварийным режимом `lab/transfer.py`; обычный hand-off их не включает. Хранилище проектов ProShow остаётся исходным материалом только для чтения.
