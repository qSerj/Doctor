# Установщик Doctor

Ставит Doctor на машину монтажёра, обновляет его поверх и удаляет. Инженер приносит папку пакета (флэшка, общая папка) и запускает `Установить.cmd`; права администратора берутся один раз, здесь. Состав и критерий — [Э6.1](../docs/plan.md), устройство процессов — [архитектура](../docs/architecture.md), «Надёжность и разделение процессов».

## Что где оказывается

| Что | Где | Кто пишет |
| --- | --- | --- |
| App и наблюдатель | `C:\Program Files\PsDoctor\App`, `\Observer` | установщик; пользователь писать туда не может, и exe помощника ETW, работающего с наивысшими правами, не подменить |
| Настройки машины | `%ProgramData%\PsDoctor\settings.json` | установщик — один раз, дальше инженер |
| Ключ наблюдателя | `%LOCALAPPDATA%\PsDoctor\observer.key` | сторож при первом запуске |
| Журналы сеансов | `%LOCALAPPDATA%\PsDoctor\observer\sessions` | наблюдатель и помощник ETW |
| Журнал сторожа | `%LOCALAPPDATA%\PsDoctor\observer\watchdog.jsonl` | сторож |
| События журнала Windows о ProShow и закладка опроса | `%LOCALAPPDATA%\PsDoctor\observer\sessions\windows-events.jsonl`, `windows-events.bookmark` | наблюдатель |
| Минидампы `proshow.exe` и `fvideo.exe` | `%LOCALAPPDATA%\PsDoctor\dumps`, не больше 5 на программу | Windows по ключу `LocalDumps`; ключ — установщик, каталог — сторож |
| Задачи | планировщик, папка `\PsDoctor\`: `watchdog` (обычные права), `etw` (наивысшие) | установщик |
| Ярлыки | «Doctor» в меню «Пуск» и на общем рабочем столе | установщик |
| Автозапуск App | ярлык «Doctor» с ключом `--tray` в личной автозагрузке монтажёра (`…\Start Menu\Programs\Startup`) | установщик |

Ключ и журналы установщик не трогает: поэтому обновление их не теряет. Профиль монтажёра он находит по SID в `ProfileList` — только чтобы положить ярлык автозагрузки и при удалении спросить о журналах. Задачи и ярлык ставятся учётной записи, которая сидит за консолью; другую можно назвать ключом `-User`.

Ключ минидампов — `HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\<программа>` и то же под `WOW6432Node`: ProShow 32-битный, и 32-битный пробник на стенде дамп получил ([Э6.2](../docs/plan.md), критерий 7); какое из двух представлений прочитала Windows, не выяснялось. Значения — `DumpFolder` `%LOCALAPPDATA%\PsDoctor\dumps` (`REG_EXPAND_SZ`, раскрывается у того, у кого упало), `DumpType` 1 (мини), `DumpCount` 5. Установщик пишет только эти значения своих ключей, удаление снимает ключи целиком; дампы остаются вместе с журналами — по вопросу.

## Процессы

Задачи две, а не три. **Сторож** (`PsDoctor.Observer.exe --watchdog`) запускает наблюдатель своим дочерним процессом с ключами из настроек, опрашивает `/health` и перезапускает его, если тот вышел или `misses` раз подряд не ответил. Каждый запуск и перезапуск — строка в журнале сторожа. Убивается только наблюдатель, не дерево: ProShow, запущенный наблюдателем, переживает перезапуск. **Помощник ETW** (`--etw-helper`) — отдельная задача с наивысшими правами; сторож его не трогает. У обеих задач к триггеру входа добавлен повтор раз в минуту бессрочно: пока экземпляр жив, `IgnoreNew` его гасит, упавший сторож или помощник поднимается не позже чем через минуту. Приоритет задач — 5, обычный: по умолчанию 7, ниже обычного, и его наследовали бы наблюдатель, помощник и ProShow, запущенный наблюдателем. Обновление сначала выключает задачи — повтор не поднимет сторожа посреди копирования, — а `Register-ScheduledTask -Force` ставит их снова включёнными.

Сторож при старте находит ProShow — `programPath` из настроек как есть, иначе программа ассоциации `.psh`, если это `proshow.exe`, иначе `Photodex\ProShow Producer\proshow.exe` в Program Files (x86) и Program Files, иначе обычное место — пишет строку `program-resolved {path, source, exists}` и передаёт путь наблюдателю ключом `--program`. App ищет тем же порядком. Дежурство включает `"watch": true` шаблона. Путь, есть ли файл и включено ли дежурство — в `/health`: в первый вечер у монтажёра это проверяется одним запросом.

App при входе запускается ярлыком автозагрузки с `--tray` — только значок, без окна. Ярлык запускает проводник, поэтому App и ProShow, открытый из App, идут с обычным приоритетом и без повышения прав. После установки и обновления App инженер запускает сам ярлыком на рабочем столе.

App находит наблюдатель по настройкам и ключу. Переменные `PSDOCTOR_OBSERVER_URL` и `PSDOCTOR_OBSERVER_KEY_FILE`, если заданы, главнее: они для инженера и стенда.

## Хранение журналов

Наблюдатель удаляет сеансы при старте и после каждого закрытого сеанса. Обычный сеанс живёт `days` дней, помеченный — `markedDays`; помечен сеанс, начатый мастером App, и сеанс с фактом `episode`. Файлы меток и событий журнала Windows хранение не удаляет: файл событий сам держится в 10 МБ, уходя в `.old`. Сверх `megabytes` уходят старейшие обычные, помеченные — только когда обычных не осталось. Шаблон — 30 дней, 8192 МБ, помеченные 180 дней: под журналы дежурства у монтажёра можно отдать около 8 ГБ (владелец, 28.09.2026). Вес — из сеанса рендера `e43-render-002`: 12,5 мин рендера — около 30 МБ журнала и сырья ETW.

## Команды

```
install/package.sh [каталог]        на хосте: собрать пакет, по умолчанию в artifacts/doctor
Установить.cmd                      в пакете: установить или обновить поверх
Удалить.cmd                         в пакете или в каталоге установки: удалить; журналы — по вопросу
Install-Doctor.ps1 -Uninstall -RemoveData yes|no -NoPause   то же без вопросов
```

Инженер подключается к наблюдателю из локальной сети: по умолчанию `"listen": "0.0.0.0:8100"` и `"allowNetworks": ["192.168.0.0/24"]` (решение владельца 28.09.2026). Запросы с петли проходят всегда, из других сетей — отказ 403 до проверки ключа. Правил брандмауэра установщик не создаёт: на машине монтажёра брандмауэра Windows нет, стоит Kaspersky Internet Security, а VPN пускает локальный трафик напрямую. Только петля — `"listen": "127.0.0.1:8100", "allowNetworks": []`. Настройки пишутся при первой установке и при обновлении не меняются: старый файл с `127.0.0.1` правится руками или удаляется перед обновлением. После правки перезапускается задача `\PsDoctor\watchdog`, или пользователь выходит из системы и входит заново.

## Чего здесь нет

Автообновления — обновляет инженер. Службы — [архитектура](../docs/architecture.md). Реестра инструментов — Э4.1. Записи в «Программах и компонентах» — удаление идёт через `Удалить.cmd`. Запуска App в конце установки — его делает инженер.

Установщик требует pwsh 7.6 или новее и Windows 10 1809 или новее (`conhost --headless`). pwsh стоит и на стенде, и у монтажёра (владелец, 25.09.2026); без него `.cmd` говорит, чего не хватает, и выходит.
