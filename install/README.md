# Установщик Doctor

Ставит Doctor на машину монтажёра, обновляет его поверх и удаляет. Инженер приносит папку пакета (флэшка, общая папка) и запускает `Установить.cmd`; права администратора берутся один раз, здесь. Состав и критерий — [Э6.1](../docs/plan.md), устройство процессов — [архитектура](../docs/architecture.md), «Надёжность и разделение процессов».

## Что где оказывается

| Что | Где | Кто пишет |
| --- | --- | --- |
| App и наблюдатель | `C:\Program Files\PsDoctor\App`, `\Observer` | установщик; пользователь писать туда не может, и exe помощника ETW, работающего с наивысшими правами, не подменить |
| Настройки машины | `%ProgramData%\PsDoctor\settings.json` | установщик — один раз, дальше инженер |
| Ключ наблюдателя | `%LOCALAPPDATA%\PsDoctor\observer.key` | сторож при первом запуске |
| Журналы сеансов | `%LOCALAPPDATA%\PsDoctor\observer\sessions` | наблюдатель и помощник ETW |
| Журнал сторожа | `%LOCALAPPDATA%\PsDoctor\observer\watchdog.jsonl` | сторож |
| Задачи | планировщик, папка `\PsDoctor\`: `watchdog` (обычные права), `etw` (наивысшие) | установщик |
| Ярлыки | «Doctor» в меню «Пуск» и на общем рабочем столе | установщик |

Ключ и журналы установщик не трогает: поэтому обновление их не теряет, а установщику не нужно знать, чей это профиль. Задачи ставятся учётной записи, которая сидит за консолью; другую можно назвать ключом `-User`.

## Процессы

Задачи две, а не три. **Сторож** (`PsDoctor.Observer.exe --watchdog`) запускает наблюдатель своим дочерним процессом с ключами из настроек, опрашивает `/health` и перезапускает его, если тот вышел или `misses` раз подряд не ответил. Каждый запуск и перезапуск — строка в журнале сторожа. Убивается только наблюдатель, не дерево: ProShow, запущенный наблюдателем, переживает перезапуск. **Помощник ETW** (`--etw-helper`) — отдельная задача с наивысшими правами; сторож его не трогает. У обеих задач стоит перезапуск планировщиком при сбое; на стенде он не проверялся.

App находит наблюдатель по настройкам и ключу. Переменные `PSDOCTOR_OBSERVER_URL` и `PSDOCTOR_OBSERVER_KEY_FILE`, если заданы, главнее: они для инженера и стенда.

## Хранение журналов

Наблюдатель удаляет сеансы при старте и после каждого закрытого сеанса. Обычный сеанс живёт `days` дней, помеченный — `markedDays`; помечен сеанс, начатый мастером App, и сеанс с фактом `episode`. Сверх `megabytes` уходят старейшие обычные, помеченные — только когда обычных не осталось. Первые числа — из веса сеанса рендера `e43-render-002`: 12,5 мин рендера — около 30 МБ журнала и сырья ETW.

## Команды

```
install/package.sh [каталог]        на хосте: собрать пакет, по умолчанию в artifacts/doctor
Установить.cmd                      в пакете: установить или обновить поверх
Удалить.cmd                         в пакете или в каталоге установки: удалить; журналы — по вопросу
Install-Doctor.ps1 -Uninstall -RemoveData yes|no -NoPause   то же без вопросов
```

Сеть наружу установщик не открывает. Чтобы инженер подключался из локальной сети, в настройках ставится `"listen": "0.0.0.0:8100"` и `"allowRemote": true`, а в брандмауэре — правило на порт 8100 только для адреса инженера; после правки — перезапуск задачи `\PsDoctor\watchdog` или выход и вход пользователя.

## Чего здесь нет

Автообновления — обновляет инженер. Службы — [архитектура](../docs/architecture.md). Реестра инструментов — Э4.1. Записи в «Программах и компонентах» — удаление идёт через `Удалить.cmd`. Автозапуска App при входе — Э6.1 его не требует.

Установщик требует Windows PowerShell 5.1 и Windows 10 1809 или новее (`conhost --headless`). Файл `Install-Doctor.ps1` хранится в UTF-8 с BOM: без BOM PowerShell 5.1 читает кириллицу как ANSI.
