# PsDoctor.Core

Ядро: модель файла шоу, правила приёмки, арифметика, записи фактов и разбор сценариев. Windows не нужен, пакетов нет ни одного.

## Граница

Сюда не попадает ничего, что открывает файл, спрашивает операционную систему или знает про время. Разбор получает `TextReader`, инвентарь — готовый каталог медиа, исполнитель сценария — канал сигналов; время приходит тиком снаружи. По этому шву тесты обходятся без Windows и без файлов, и он же делает CLI переносимым.

Одно исключение названо в [архитектуре](../../docs/architecture.md): `ProShowWindows` в `Observation/ProgramFacts.cs` — заголовки окон чужой программы и номер пункта меню, нужные ожиданию `wait render-done`. Это долг, а не образец: следующее правило такого рода выносит имена окон в данные сеанса.

## С чего читать

| Хочу понять | Начинать с |
| --- | --- |
| как читается `.psh` | `ShowFile.cs`, дальше `Format/ShowFileParser.cs` |
| что доктор знает о проекте | `Model/Show.cs` и `Inventory/Inventory.cs` |
| как устроена находка | `Rules/Finding.cs`, затем `Rules/AcceptanceRules.cs` |
| что выходит в stdout | `Reporting/ReportBuilder.cs` |
| что такое факт наблюдения | `Observation/Fact.cs` и `Observation/FactLog.cs` |
| как выполняется сценарий | `Scenarios/ScenarioExecutor.cs` |

## Чего здесь нет

Порогов у правил — ни у одного, и это решение, а не недоделка: правило считается всегда, порог даст [Э2.2](../../docs/plan.md). Исключений на содержимое файла шоу — парсер не бросает их вовсе, продукт существует ради сломанных проектов. Человеческих фраз — слова живут в окне.

## Тесты

`tests/PsDoctor.Core.Tests`. Синтетика — `SyntheticShow.cs`, боевые проекты ищутся на машине и молча пропускаются, когда материала нет (`BattleProject.cs`).
