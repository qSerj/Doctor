# PsDoctor.App

Пользовательский Doctor на Avalonia. Компактное окно и трей дают обычное открытие `.psh`, холодную проверку проекта, рекомендации и безопасное исправление известных кэшей. Закрытие окна прячет его в трей; «Выход» завершает Doctor. Выбранный для проверки файл не считается автоматически открытым в ProShow.

## Что здесь будет

Рабочее поведение задано [спецификацией интерфейса](../../design/field-ui/README.md). Для диагностического запуска App использует Observer.Client только с шагом `launch` и завершает наблюдение через `Stop`, не закрывая ProShow. Адрес и путь к ключу задаются переменными `PSDOCTOR_OBSERVER_URL` и `PSDOCTOR_OBSERVER_KEY_FILE`; без них действие явно недоступно. Для странного поведения и ручного рендера App пассивно подключается к уже работающему ProShow и показывает, когда запись ETW неполная. Отсутствие рекомендаций не объявляется гарантией здоровья проекта.

Команда работает с узким списком: `proshow.phd` в каталоге программы и его зеркале `VirtualStore`, а после выбора `.psh` — одноимённый `.pxc` рядом с ним. Каждый существующий файл переименовывается рядом с исходным и может быть возвращён вручную. `proshow.cfg`, `autosave.psh`, временные файлы, медиа и сам `.psh` не трогаются. При работающем ProShow ничего не переименовывается; приложение просит сохранить работу и закрыть программу вручную. Если доступа к кэшу в `Program Files` нет, результат показывает частичное выполнение.

## Граница

**Слова живут здесь и только здесь.** В отчёте CLI и в фактах наблюдателя человеческих фраз нет вовсе.

**Окно не повышается в правах.** Это не осторожность: у процесса с повышенными правами перестаёт работать перетаскивание файлов из проводника, и доктор не смог бы принять брошенный мышкой файл шоу.

Avalonia, а не WPF: WPF навсегда закрыл бы общий код с соседним проектом владельца.

## Проверка

`dotnet test tests/PsDoctor.Infrastructure.Tests --filter FullyQualifiedName~ProShowCacheCleanerTests` проверяет точный набор файлов, сохранение байтов и отказ при работающей программе. Сборка App и короткий запуск на Windows проверяют загрузку окна и значка трея. На машине Оли перед первым действием проверить путь установленного ProShow и наличие файлов в его реальном профиле.
