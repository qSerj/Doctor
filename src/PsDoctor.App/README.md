# PsDoctor.App

Пользовательский Doctor на Avalonia. Компактное окно и трей дают обычное открытие `.psh`, холодную проверку проекта, рекомендации и мастер «Решить проблему». Мастер не спрашивает ни симптом, ни проект: сначала быстрое восстановление служебных файлов, потом наблюдение за ProShow; запуск под наблюдением предлагает ProShow без проекта или с проектом; технические названия файлов оператору не показываются. Doctor один на пользователя: второй запуск показывает окно первого. При входе монтажёра App запускает ярлык автозагрузки с ключом `--tray` — только значок, без окна; второй запуск с `--tray` окна первого не будит. ProShow App ищет тем же порядком, что сторож (`ProShowLocator`: `programPath` из настроек, ассоциация `.psh`, Program Files), — от этого пути зависят чистка кэша и проверка диска ([Э6.2](../../docs/plan.md), часть Д). Выбранный проект забывается крестиком в шапке. Закрытие окна прячет его в трей; «Выход» завершает Doctor. Выбранный для проверки файл не считается автоматически открытым в ProShow.

Это самостоятельное приложение монтажёра без технической подготовки; удобство и понятность во главе угла. Роль решена [вторым раундом](../../design/tier2/roles.md): **App применяет готовые рецепты** — узнал известную проблему, дал совет с понятным действием, не узнал — молчит. Рецепты создаются в `PsDoctor.Workbench` опытами инженера и агента; Workbench не подменяет это окно и не предназначен для обычной работы монтажёра.

## Что здесь будет

Рабочее поведение задано [спецификацией интерфейса](../../design/field-ui/README.md). Для диагностического запуска App использует Observer.Client только с шагом `launch` и завершает наблюдение через `Stop`, не закрывая ProShow. Адрес берётся из настроек машины, ключ — из профиля, куда его кладёт сторож ([установщик](../../install/README.md)); переменные `PSDOCTOR_OBSERVER_URL` и `PSDOCTOR_OBSERVER_KEY_FILE`, если заданы, главнее — для инженера и стенда. Без того и другого действие недоступно, и мастер просит позвать администратора. Сеансы мастера помечаются `origin: wizard` и хранятся дольше. Если ProShow открыт, App пассивно подключается к нему и показывает, когда запись ETW неполная. Кнопка «Закончить наблюдение» видна, пока идёт сеанс; она и «Выход» из трея останавливают сеанс, не закрывая ProShow. Если ProShow не запущен, мастер объясняет, что прошлый сбой не записан, и предлагает запустить проект под наблюдением. Отсутствие рекомендаций не объявляется гарантией здоровья проекта.

С Э6.2 (часть Б) мастер первым действием, до любого окна, ставит метку инцидента у наблюдателя (не дольше 5 с) и пробует ProShow только чтением (`ProShowProbe`: процессы куста, главное окно, «не отвечает», процессор и ввод-вывод). Наблюдатель недоступен — метка остаётся строкой `incident` в истории мастера. Идущий сеанс, дежурства или мастера, App себе не забирает и нового не начинает; отказ подключения `program-running` значит, что запись уже идёт. Повторное нажатие при открытом мастере — только ещё одна метка. Не отвечающий или живой без окна ProShow ведёт в окно ожидания: первые 60 с — «не закрывайте ProShow», дальше «занят, подождите» или кнопка «Завершить ProShow» с подтверждением — только для процесса без окна дольше минуты или окна, которое не отвечает 3 мин при почти нулевом процессоре и вводе-выводе куста за последние 60 с; при рендере — никогда. Пороги — `ProShowHangWatch`, назначены, не измерены. Завершается только найденный процесс, сверенный по номеру и времени создания, перед этим — метка с пояснением. Статус окна и трея «ProShow не отвечает» при 30 с подряд главнее прочих. Неудачи восстановления считаются за 14 дней; про попытку старше двух суток «помогло ли» не спрашивается, она получает ответ `unknown`. Необработанное исключение пишется в `%LOCALAPPDATA%\PsDoctor\app-errors.jsonl`, на потоке окна гасится.

Внутренний быстрый рецепт работает с узким списком служебных файлов: `proshow.phd` в каталоге программы и его зеркале `VirtualStore`, а после выбора `.psh` — одноимённый `.pxc` рядом с ним. Каждый существующий файл переименовывается рядом с исходным и может быть возвращён вручную. `proshow.cfg`, `autosave.psh`, временные файлы, медиа и сам `.psh` не трогаются. При работающем ProShow ничего не переименовывается; мастер просит сохранить работу и закрыть программу вручную. Номер, время и результат попыток пишутся в `%LOCALAPPDATA%\PsDoctor\repair-history.jsonl`.

Совет по эпизоду детектора ([Э4.4](../../docs/plan.md)): раз в 5 с App смотрит живой сеанс наблюдателя — любой, в том числе дежурства — и читает из него поток одних фактов `episode`. Эпизод `qtime-loop` при галке «Avoid using DirectShow», не отмеченной в действующем `proshow.cfg`, даёт жёлтую полосу «ProShow не может показать видео» с кнопкой «Исправить» и статус «Есть совет». Кнопка работает только при закрытом ProShow: он переписывает `proshow.cfg` при запуске. `ProShowVideoImportFix` берёт тот же действующий файл, что слепок окружения, кладёт его копию в `%LOCALAPPDATA%\PsDoctor\backup\proshow.cfg.<время>` и меняет один байт `0` на `1`. Файл неизвестен, настройки в нём нет или записать нельзя — App говорит, где отметить галку руками. Полоса уходит, когда галка отмечена любым путём.

Решено, но в коде нет ([сценарии М1–М6](../../design/tier2/roles.md)): перетаскивание `.psh` на окно; кнопка рекомендации о материале, зовущая внешний перекодировщик с готовыми параметрами; откат к резервным срезам `.bNN` в копию.

## Граница

**Слова живут здесь и только здесь.** В отчёте CLI и в фактах наблюдателя человеческих фраз нет вовсе.

**Окно не повышается в правах.** Это не осторожность: у процесса с повышенными правами перестаёт работать перетаскивание файлов из проводника, и доктор не смог бы принять брошенный мышкой файл шоу.

Avalonia, а не WPF: WPF навсегда закрыл бы общий код с соседним проектом владельца.

**Вид задаётся одним набором стилей в `App.axaml`.** Тоны `ok`, `warn`, `error`, `watch`, `info` и `idle` — это классы. Из них собраны карточки действий, круглые значки и плашки. Синей (`primary`) бывает одна кнопка — следующий шаг. Значки — Microsoft Fluent UI System Icons (MIT): их контуры лежат в `Assets/Icons.axaml`, лицензия — рядом, NuGet-пакета с иконками нет. Значок программы — доктор с чемоданчиком (картинка владельца, `Assets/doctor-source.webp`): целиком — в `doctor.ico` для exe и ярлыков, голова — в `doctor-tray.ico` для трея и окна. Оба `.ico` собирает `Assets/make-icons.py` (Pillow).

## Проверка

`dotnet test tests/PsDoctor.Infrastructure.Tests --filter FullyQualifiedName~ProShowCacheCleanerTests` проверяет точный набор файлов, сохранение байтов и отказ при работающей программе; `RepairHistoryTests` — историю попыток мастера, сроки и переходы после ответа оператора; `ProShowHangWatchTests` — когда ждать, а когда предлагать завершение. Сборка App и короткий запуск на Windows проверяют загрузку окна и значка трея. На машине Оли перед первым действием проверить путь установленного ProShow и наличие файлов в его реальном профиле.
