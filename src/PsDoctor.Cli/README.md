# PsDoctor.Cli

Две разные команды под одним именем: приёмочный прогон файла шоу и `observe` — разговор с [наблюдателем](../PsDoctor.Observer/README.md).

## Граница

Вывод **машинный**: отчёт — JSON Lines, строка на файл, человеческих фраз нет. Отчёт только в stdout, диагностика только в stderr. Лечить CLI не умеет и в чужой каталог не пишет никогда: прогон пачки проектов остаётся чистым чтением.

## Две роли и две таблицы кодов

`psdoctor <файл.psh>` (`Runner.cs`): 0 — разобран, находок нет; 1 — есть находки, прошедшие порог; 2 — не файл шоу; 3 — сбой окружения. Код 1 сегодня недостижим, потому что порогов нет ни у одного правила.

`psdoctor observe <команда>` (`ObserveCommand.cs`): 0 — выполнено; 1 — сценарий не выполнен; 2 — отказ наблюдателя; 3 — сбой окружения. Адрес и ключ — `PSDOCTOR_OBSERVER_URL` и `PSDOCTOR_OBSERVER_KEY_FILE` или ключи командной строки.

Таблицы разные по смыслу, и путать их нельзя. Список команд `observe` смотреть не здесь, а в `observe help`: он печатается кодом и не устаревает.

## Чего здесь нет

Слов для человека, лечений, записи куда бы то ни было. Разбора того, что приходит от наблюдателя: факты уходят в stdout как есть, тем же видом, что лежат в журнале сеанса.

## Тесты

`tests/PsDoctor.Cli.Tests`. `ObserveCommandTests` работают на подменённом `HttpMessageHandler` — наблюдатель для них не нужен.
