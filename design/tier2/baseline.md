Чего нет: перетаскивания `.psh` на окно (сценарий М1 — только через выбор файла); распознавания паттернов и советов по ним (М4); дежурства (М5); отката к срезам (М6); кнопок действия у рекомендаций (М3); настроек («Настройки пока недоступны»). Observer находится только по переменным `PSDOCTOR_OBSERVER_URL` и `PSDOCTOR_OBSERVER_KEY_FILE`. App использует из сценариев только `launch`; `press`, `render`, `close` не посылает.

| Пассивный сеанс `attach` без задания, запрет команд на сервере | реализовано (Э4.3), скорее не проверено |

Запуск: две задачи планировщика при входе пользователя — Observer с ограниченными правами, помощник с наивысшими; ставит их скрипт стенда `lab/guest/Deploy-Observer.ps1`. Сторожа нет: зависший Observer никто не заметит. Один живой сеанс на процесс. Срока хранения журналов нет. Заголовки окон читаются без сообщений зависшей программе; `press` может ждать зависший ProShow — это только сценарии запуска.

### Установка

`lab/deploy.sh` собирает CLI, App, Workbench и Observer под `win-x64` в новый релиз; `lab/guest/Install-PsDoctor.ps1` ставит и останавливает Doctor перед установкой. Это оснастка стенда, не продукт: ключ, адрес и задачи планировщика ставит отдельный скрипт стенда, App о них не знает.

## Что это значит для раунда

Код ушёл дальше документов в наблюдении и в App, а документы — дальше кода в лечении проектов. Второе теперь под вопросом у владельца, первое не записано нигде, кроме README проектов. Самые большие пробелы относительно согласованной модели: нет пути рецепта до App (И3), нет установщика (И4), Observer у Оли не спроектирован как часть поставки, видео не измеряется — а без этого не будет ни М3 про кодеки, ни исследования подёргивания.
